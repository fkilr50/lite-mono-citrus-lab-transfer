Root Cause Analysis

1. Metric Mismatch Between Training and Evaluation

Self-supervised training optimizes:

L_photo = |I_current - warp(I_next, predicted_depth, predicted_pose)|

But evaluation measures:

L_depth = |predicted_depth - LiDAR_depth|

These are fundamentally different objectives. In vegetation, multiple wrong depths can produce low photo loss.

2. Vegetation Creates Ambiguity

In dense citrus canopy:
  • Canopy has self-similar texture at many depths
  • Leaves at 2m look like leaves at 4m
  • Photo loss says both depths are equally good
  • Model picks either one arbitrarily
  • Result: No guarantee the prediction is correct

3. Batch Normalization Buffer Drift

Even with frozen encoder weights:

  • 18 BatchNorm layers still in train mode
  • BN running statistics (buffers) not frozen
  • Small batch (4) = noisy statistics
  • 1069 batches over 1000 steps corrupts all buffers
  • Frozen weights + drifted BN = representation corruption

4. Insufficient Regularization

  • Smoothness loss: 0.001 × L_total
  • Photo loss: ~0.99 × L_total
  • Photo loss is 1000x stronger
  • Smoothness cannot prevent structure from breaking

Recommended Solution for Milestone 4

Add Relative Depth Ranking Loss

Core Idea: LiDAR tells us which pixels are closer/farther. Make predictions respect those orderings.

For each pixel pair (i, j):
  sign_gt = sign(depth_LiDAR[i] - depth_LiDAR[j])
  sign_pred = sign(depth_pred[i] - depth_pred[j])
  
L_relative = mean( |sign_gt - sign_pred| )
L_total = L_photo + λ_rel * L_relative + λ_smooth * L_smooth
✓ Why This Works:
  • Protects relative structure (what a1 metric cares about)
  • Doesn't over-constrain absolute scale
  • Removes vegetation ambiguity via LiDAR constraints
  • Complements photo loss rather than competing
  • Among all photo-good solutions, picks depth-good ones
